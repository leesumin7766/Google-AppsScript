# 시트 계약 (SHEET_CONTRACT) — schema 1

Flow(Apps Script)와 ATDT(Electron)가 함께 쓰는 구글 시트 **시험일정요약** 의 구조와 규칙입니다.
두 프로그램은 서로 직접 호출하지 않고 이 시트만 접점으로 씁니다. **이 문서만 보고 시트를 읽고, `확인 큐` 의 `처리` 열과 `할 일` 의 `상태` 열을 쓸 수 있어야 합니다.**

- 기준 코드: Flow v1.7 (`Config.gs`·`Tabs.gs`·`Utils.gs`·`Writer.gs`·`Llm.gs`)
- 스키마 버전: **1** (아래 [스키마 버전](#7-스키마-버전과-바꾸는-절차))
- 이 문서의 탭 표(열·이름)는 테스트(`tests/run.test.js` 의 `[계약]`)가 코드의 머리글 상수와 맞는지 확인합니다.

---

## 0. 공통 규칙

| 항목 | 규칙 |
|---|---|
| 탭 찾기 | 탭 **이름**으로 찾습니다. 탭 순서는 바뀔 수 있습니다 |
| 열 찾기 | 열 **글자**가 아니라 **머리글 이름**으로 찾습니다. 머리글의 괄호 앞부분을 앞뒤 공백을 지우고 키로 씁니다: `담당자 (고객사 연락처/직함)` → `담당자`. (`마스터` 만 해당. 다른 탭의 머리글에는 괄호가 없습니다) |
| 날짜 | `yyyy-MM-dd` (Asia/Seoul) 하나로 비교·기록합니다. 시트가 문자열을 날짜로 바꿔 저장하므로, 읽는 쪽은 **날짜 값(Date·일련번호)과 문자열을 모두** `yyyy-MM-dd` 로 맞춰 읽습니다 |
| 시각 | `yyyy-MM-dd HH:mm:ss` (Asia/Seoul). 날짜와 같은 까닭으로 날짜시간 값으로 읽힐 수 있습니다 |
| 빈칸 | 빈 문자열과 빈 셀은 같습니다 |
| 메시지ID | Gmail 메시지 ID (`GmailMessage.getId()`, 16진수 문자열) |
| 시험번호 | `[영문]-[2자리]-[숫자]` (예: `TTA-26-00001`). 대소문자를 무시하고 비교합니다 (Flow 는 대문자로 씁니다) |
| 행 지우기·순서 바꾸기 | ATDT 는 하지 않습니다. 사람은 `처리로그` 행만 재테스트용으로 지울 수 있습니다 |
| 잠금 | Flow 의 쓰기는 `LockService` 로 한 번에 하나만 돕니다. ATDT 쓰기는 한 칸씩 짧게 하고, 아래 "ATDT 가 쓰는 칸" 밖은 쓰지 않습니다 |

**쓰는 쪽** 표기: `Flow` = Flow 코드, `사람` = 시트에서 사람이 직접, `ATDT` = ATDT 허브. 표에 없는 쪽은 그 칸을 **읽기만** 합니다.

Flow 는 시작할 때 자신이 쓰는 열(`쓰는 쪽` 에 Flow 가 있는 열)이 1행에 있는지 보고, 없으면 실행 로그에 `마스터 1행에 없는 열: …` 을 남깁니다. `시험번호` 열이 없으면 진행 메일 처리를 멈춥니다.

규칙:
- LLM 이 바꿀 수 있는 열은 `시험시작일`·`1차결함`·`2차결함`·`3차결함`·`패치`·`시험종료일`·`상태` 뿐입니다(`ALLOWED_COLUMNS`). 확인 큐 `적용` 도 이 열만 씁니다.
- 날짜 순서: `시험시작일` ≤ `1차결함` ≤ `2차결함` ≤ `3차결함`, `패치` ≤ `시험종료일`. 어긋나는 값은 Flow 가 쓰지 않고 확인 큐로 보냅니다.
- Flow 는 값이 있는 칸을 덮어쓰지 않습니다(같으면 건너뛰고, 다르면 확인 큐). 덮어쓰는 것은 사람이 확인 큐에서 `적용` 할 때뿐입니다.
- 새 행 위치: 수식 열을 뺀 모든 열에서 마지막으로 값이 있는 행의 다음 행(최소 3행). 시험번호가 빈 행도 데이터가 있는 행입니다.
- `종료`·`중단` 행은 메일 도메인으로 시험번호를 찾을 때 보지 않습니다.
- **ATDT 는 `마스터` 에 쓰지 않습니다.** 값을 바꾸려면 확인 큐를 통해야 합니다.

## 3. `처리로그`

메일 1건 = 1행. Flow 만 씁니다. ATDT 는 읽기만 합니다.

| 열 | 이름 | 쓰는 쪽 | 형식·허용값 | 설명 |
|---|---|---|---|---|
| A | `메시지ID` | Flow | 메시지ID | 같은 ID 가 여러 행이면 아래쪽 행이 유효 |
| B | `처리 시각` | Flow | 날짜시간 | 메일의 받은 시각 (처리한 시각이 아님) |
| C | `결과` | Flow | 문자열 | 사람이 읽는 결과 설명 |
| D | `상태` | Flow | `완료`·`재시도대기`·`포기`·`확인대기` | 빈칸(v1.4 이전 행)은 `완료` 로 봄 |
| E | `시도횟수` | Flow | 숫자 또는 빈칸 | LLM 을 부른 횟수. 최대 3 |

- `재시도대기` 인 메일만 다음 실행에서 다시 처리합니다(같은 행을 고침). 나머지 상태는 다시 처리하지 않습니다.
- 행을 지우면 그 메일을 다시 처리합니다(재테스트용, 사람만).
- `DRY_RUN` 실행은 처리로그에 쓰지 않습니다.

## 4. `확인 큐`

Flow 가 자동으로 정하지 못한 **변경 1건 = 1행**. 메일 1건이 여러 행이 될 수 있습니다. Flow 는 행을 아래에 덧붙이기만 하고, 지우거나 옮기지 않습니다.

| 열 | 이름 | 쓰는 쪽 | 형식·허용값 | 설명 |
|---|---|---|---|---|
| A | `ID` | Flow | `Q-<메시지ID>-<n>` (n 은 1부터) | 행 식별자 |
| B | `생성시각` | Flow | 시각 | |
| C | `시험번호` | Flow | 시험번호 또는 빈칸 | 시험번호를 못 찾은 메일이면 빈칸 |
| D | `메시지ID` | Flow | 메시지ID | 원본 메일 |
| E | `메일 링크` | Flow | `https://mail.google.com/mail/u/0/#all/<threadId>` | 보관함 메일도 열림. 스레드 단위 |
| F | `열` | Flow | 마스터 키 또는 `시험번호` 또는 빈칸 | 바꿀 마스터 열 |
| G | `기존값` | Flow | 날짜·문자열·빈칸 | 큐에 넣을 때 마스터의 값 |
| H | `제안값` | Flow, 사람·ATDT | 날짜·상태 허용값 | `적용` 전에 고쳐도 됨 |
| I | `사유` | Flow | 문자열 | 왜 확인이 필요한지. `적용` 이 거절되면 Flow 가 ` / 적용 안 함(<시각>): <까닭>` 을 덧붙임 |
| J | `LLM 원문` | Flow | JSON 문자열 (45,000자에서 자름) | 검토용 |
| K | `처리` | Flow, 사람·ATDT | `대기`·`적용`·`무시` (드롭다운) | Flow 는 `대기` 로 넣음 |
| L | `처리시각` | Flow | 시각 또는 빈칸 | **비어 있지 않으면 끝난 행** |

### ATDT·사람이 결정을 내리는 법
1. `처리시각` 이 빈 행 중 `처리` 가 `대기` 인 행이 할 일입니다.
2. 필요하면 `제안값` 을 고친 뒤, `처리` 를 `적용` 또는 `무시` 로 바꿉니다. **다른 칸은 쓰지 않습니다**(특히 `처리시각`).
3. Flow 가 반영합니다: 사람이 시트에서 바꾸면 onEdit 트리거가 바로, ATDT 가 API 로 바꾸면 **다음 매시간 실행 시작 때**. (API 쓰기는 onEdit 를 일으키지 않습니다)
4. 결과는 같은 행에서 읽습니다:

| 결과 | `처리` | `처리시각` | `사유` |
|---|---|---|---|
| 무시됨 | `무시` | 채워짐 | 그대로 |
| 적용됨 (마스터에 씀) | `적용` | 채워짐 | 그대로 |
| 적용 거절 | `대기` 로 되돌아감 | 빈칸 | `/ 적용 안 함(…): …` 이 붙음 |

`적용` 이 거절되는 경우(마스터는 바뀌지 않음):
- `열` 이 `ALLOWED_COLUMNS` 밖 — **`열` 이 `시험번호` 이거나 빈 행은 늘 거절됩니다.** 메일을 열어 직접 처리하고 `무시` 로 닫습니다.
- `제안값` 이 형식에 안 맞음 (`상태` 는 허용값, 날짜 열은 날짜로 읽혀야 함)
- 마스터에 그 시험번호 행이나 열이 없음
- 마스터의 현재 값이 `기존값` 과 다름 (그사이 누가 고침 → 덮어쓰지 않음)

## 5. `할 일`

LLM 이 메일에서 뽑은 할 일 1건 = 1행. 나중에 ATDT 가 옵시디언 일일노트로 가져갑니다.

| 열 | 이름 | 쓰는 쪽 | 형식·허용값 | 설명 |
|---|---|---|---|---|
| A | `ID` | Flow | `T-<메시지ID>-<n>` (n 은 1부터) | 행 식별자 |
| B | `시험번호` | Flow | 시험번호 | |
| C | `내용` | Flow | 문자열 | |
| D | `기한` | Flow | 날짜 또는 빈칸 | |
| E | `출처 메시지ID` | Flow | 메시지ID | |
| F | `생성시각` | Flow | 시각 | |
| G | `상태` | Flow, ATDT·사람 | `신규`·`반영`·`무시` (드롭다운) | Flow 는 `신규` 로 넣고 다시 바꾸지 않음 |

- ATDT 는 `상태` 가 `신규` 인 행을 가져가고, 일일노트에 넣었으면 `반영`, 넣지 않기로 했으면 `무시` 로 바꿉니다. 다른 칸은 쓰지 않습니다.
  - (2026-11-06, ATDT `dev-integration`) ATDT 는 쓰기 직전에 그 행을 다시 읽어 아직 `신규` 일 때만 `반영` 으로 바꾸고, 할 일은 ATDT 앱 안 오늘 할 일에 넣습니다(옵시디언 파일은 쓰지 않음). `무시` 는 쓰지 않습니다. `반영` 을 쓴 뒤 앱 저장이 실패하면 자기가 쓴 `반영` 을 `신규` 로 되돌릴 수 있습니다(허용값·쓰는 칸은 그대로라 스키마 변경 아님).
- "오늘 이후 할 일만 넣기" 같은 규칙은 ATDT 쪽에서 적용합니다.
- Flow 는 `시험번호`(대소문자 무시)·`내용`(앞뒤 공백 무시)·`기한` 이 같은 행이 이미 있으면 새로 넣지 않습니다(상태와 관계없이). 그래서 `무시` 한 할 일도 다시 생기지 않습니다.
- 확신도가 낮은 메일의 할 일은 넣지 않습니다.

## 7. 스키마 버전과 바꾸는 절차

- `설명` 탭에 **`schema: 1`** 이라고 적힌 셀이 하나 있습니다(위치는 자유. 읽는 쪽은 `설명` 탭에서 `schema:` 로 시작하는 첫 셀을 찾습니다).
- ATDT 는 시작할 때 이 숫자를 읽고, 자신이 아는 버전과 다르면 **쓰기를 멈추고** 읽기만 합니다.
- 다음을 바꾸면 버전을 올립니다: 탭 이름, `확인 큐`·`할 일`·`처리로그` 의 열 이름·순서, 허용값, ID 규칙, 마스터의 키 이름, "쓰는 쪽".
- 바꾸는 순서: ① 이 문서를 고치고 버전을 올림 → ② Flow 코드·테스트 → ③ `설명` 탭의 숫자 → ④ ATDT.
