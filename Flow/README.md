# Flow — GS 인증 메일 → 구글 시트 자동화 엔진

Google Apps Script 프로젝트. 업체·시험 관련 Gmail 을 읽어 **구글 시트(시험일정요약, `마스터` 탭)** 를 자동으로 갱신합니다.
목표는 완전 자동화가 아니라 **약 80% 자동화**입니다. 확실한 것은 자동으로 넣고, 애매한 것은 `확인 큐` 로 넘겨 사람이 정합니다.

현재 버전: **v1.3** — 1단계(v1.1 확인·C1~C4) 완료 (아래 [현재 상태](#현재-상태))

---

## 1. 위치와 다른 프로그램과의 관계

```
Gmail ──▶ [Flow 엔진 (이 프로젝트, Apps Script)] ──▶ 구글 시트 ◀── [ATDT 허브 (Electron, 별도 레포)]
```

- **Flow 와 ATDT 는 분리된 프로그램입니다.** 서로 직접 호출하지 않고(웹앱·API 없음) **구글 시트만 접점**으로 씁니다.
- 각자 혼자서도 동작해야 합니다.
  - Flow 단독: 사람이 시트에서 직접 `확인 큐` 를 처리합니다.
  - ATDT 단독: 시트를 읽어 보여 주기만 합니다.
- 두 프로그램의 호환은 **시트 계약(`SHEET_CONTRACT.md`)** 으로 지킵니다. 시트 구조를 바꾸면 계약 문서를 먼저 고칩니다.
- **옵시디언 연동은 보류합니다.** Flow 는 옵시디언·GitHub 에 쓰지 않습니다. LLM 이 뽑은 할 일은 시트의 `할 일` 탭에 쌓아 두고, 나중에 ATDT 가 가져가 일일노트에 넣습니다.

## 2. 파일 구조

| 파일 | 내용 |
|---|---|
| `Config.gs` | 시트 ID, 탭 이름, 헤더 행(1)·데이터 시작 행(3), 라벨명, 정규식, 모델명, 내 메일 주소. 스크립트 속성 읽기(`getSetting`, `getSpreadsheetId`, `isDryRun`) |
| `Writer.gs` | 시트 쓰기 창구. `DRY_RUN` 이면 실제 탭 대신 `시뮬레이션` 탭에 기록 |
| `Main.gs` | 트리거 진입점 `runInitiationCheck()`(매일 07시), `runProgressCheck()`(매시간) |
| `Initiation.gs` | 착수 안내 메일 → `마스터` 에 새 행 생성 |
| `Progress.gs` | GS 라벨 진행 메일 → 시험번호 매칭 → 정형 파싱 → LLM → 시트 반영 / 확인 큐 |
| `Parser.gs` | 정규식 파싱 (기본 정보·착수 메일), 인용문 절삭 `cleanEmailBody` |
| `Llm.gs` | Gemini 호출, 마스킹, 행 데이터 → 객체 변환, LLM 제안 검사 `checkLlmUpdates` (허용 열·상태값·날짜 형식·충돌) |
| `Utils.gs` | 열 맵, 헤더 정규화, 행 찾기, 새 행 위치 `findNewRowIndex`, 처리로그 |
| `Github.gs` | 옵시디언 Flow.md 갱신 — **사용 중단 예정** (3단계에서 호출 제거) |
| `appsscript.json` | 타임존 Asia/Seoul, V8 |
| `tests/` | Node 테스트 (`node Flow/tests/run.test.js`). 가짜 시트·메일로 실제 `.gs` 를 실행. Apps Script 에는 올리지 않음 |
| `.claspignore` | `clasp push` 에 `.gs`·`appsscript.json` 만 올림 |

**비밀 값**: `GEMINI_API_KEY`, `GITHUB_TOKEN` 은 코드에 두지 않고 **스크립트 속성**에만 둡니다. 코드·로그·커밋에 키를 남기지 않습니다.

**스크립트 속성 (설정)** — 모두 선택 사항이며, 없으면 `Config.gs` 값을 씁니다.

| 속성 | 뜻 |
|---|---|
| `SPREADSHEET_ID` | 대상 시트 ID. 테스트 때는 **사본** ID |
| `DRY_RUN` | `true` 면 `마스터`·`확인 큐`·`할 일`·`처리로그` 에 쓰지 않고 `시뮬레이션` 탭에만 기록. GitHub 에도 쓰지 않음 |
| `INIT_SEARCH_QUERY` | 착수 메일 검색어 (지난 메일 재처리 때 `newer_than:60d` 등으로 늘림) |
| `GS_THREAD_LIMIT` | GS 라벨에서 읽을 스레드 수 (기본 20) |

## 3. 처리 흐름

### 3-1. 착수 메일 (매일 07시)
1. `subject:"GS 시험 인증 시작 안내" newer_than:3d` 로 검색합니다. `Re:`·`Fwd:` 메일은 건너뜁니다.
2. 본문에서 상담자, 시험안내일, 시험시작일, WD, 시험원을 뽑고 상태를 `접수` 로 둡니다.
3. `마스터` 에 새 행을 만들고 처리로그에 남깁니다.
4. **사람이 할 일**: 새 행에 시험번호를 적습니다.

### 3-2. 진행 메일 (매시간)
1. `GS` 라벨이 붙은 스레드 20개를 읽습니다. 처리로그에 있는 메시지ID 는 건너뜁니다.
2. 제목에서 시험번호(`TTA-26-00001` 형식)를 찾아 `마스터` 의 행과 맞춥니다.
   - 행이 아직 없으면 로그를 남기지 않고 다음 주기에 다시 봅니다.
3. **STEP A (정형 파싱)**: 년도·기업명·담당자가 빈칸이면 채웁니다.
4. **STEP B (LLM)**: 인용문을 자르고 마스킹한 본문을 Gemini 에 보내 JSON 을 받습니다.
   - 허용된 열만 반영합니다. 충돌하거나 확신도가 낮으면 `확인 큐` 로 보냅니다.
   - 요약은 `진행상황` 에 `[MM/dd] 요약` 으로 덧붙입니다.

## 4. 시트 구조 (요약 — 상세는 `SHEET_CONTRACT.md`)

| 탭 | 쓰는 쪽 | 내용 |
|---|---|---|
| `마스터` | 사람, Flow | 건당 1행, A~AO열. **2행은 예시 데이터이므로 지우지 않습니다.** 데이터는 3행부터 |
| `처리로그` | Flow | 메시지ID, 처리 시각, 결과 (+ 상태·시도횟수 추가 예정) |
| `확인 큐` | Flow, (나중에 ATDT 는 처리결과 열만) | 사람이 결정할 변경 |
| `할 일` | Flow | LLM 이 뽑은 할 일 (3단계에서 신설) |
| `설명` | 사람 | 사용 안내 |
| `시뮬레이션` | Flow (`DRY_RUN` 일 때만) | 시각·메시지ID·시험번호·탭·행·열·기존값·새 값·사유. **사본에서만** 없으면 코드가 만듭니다. 실제 시트에서는 만들지 않고 실행을 멈춥니다 |

- **열은 글자(R열)가 아니라 헤더 이름으로 찾습니다.** 헤더의 괄호 앞부분만 키로 씁니다(`담당자 (고객사 연락처/직함)` → `담당자`).
- **날짜는 `yyyy-MM-dd`(Asia/Seoul) 한 가지 형식으로** 비교·기록합니다.
- `F열(잔여일자)` 은 수식입니다. 스크립트가 쓰지 않습니다.
- 처리로그의 행을 지우면 그 메일을 다시 처리합니다(재테스트용).

## 5. 설계 원칙

1. **LLM 은 값을 제안만 하고, 반영 여부는 코드가 정합니다.** 열 허용 목록, 날짜 형식, 상태 허용값, 날짜 순서 규칙(시작 ≤ 1차결함 ≤ 2차결함 ≤ 3차결함, 패치 ≤ 종료)은 코드로 검사합니다. 하나라도 어긋나면 확인 큐로 보냅니다.
2. **LLM 이 쓸 수 있는 열은 날짜 열과 `상태` 뿐입니다.** `담당자`(파서가 채움), `진행상황`(코드가 요약을 덧붙이고 사람이 메모함), 시험번호, 기업명, 수식 열은 LLM 이 쓰지 않습니다.
3. **외부로 보내는 정보를 최소화합니다.** LLM 에는 인용문을 자르고 전화번호·IP 를 마스킹한 본문만 보냅니다. API 키는 URL 이 아니라 헤더로 보냅니다.
4. **덮어쓰지 않습니다.** 기존 값과 같으면 건너뛰고, 다르면 확인 큐로 보냅니다. 충돌이 없는 열은 반영합니다.
5. **실패한 일을 버리지 않습니다.** 일시적 오류는 다시 시도하고, 끝내 처리하지 못한 메일은 사유와 함께 남깁니다.

### v1.3 — 1단계 완료 (2026-11-06)
v1.1 패치를 실제 실행 경로에 연결하고 C1~C4 를 고쳤습니다. `tests/` 42개 통과.

| # | 고친 내용 |
|---|---|
| C1 | 착수 메일은 `appendRow` 대신 `findNewRowIndex()` 로 새 행 위치를 정합니다: **수식 열(`CONFIG.FORMULA_COLUMNS`, 지금은 `잔여일자`)을 뺀 모든 열**에서 마지막으로 값이 있는 행 다음 행(최소 3행). 시험번호가 빈 착수 행도 상담자·시험안내일·상태가 있어 덮어쓰지 않습니다. 쓰기 직전에 대상 행이 비었는지 다시 보고, 비어 있지 않으면 처리로그 없이 넘어가 다음 주기에 다시 봅니다. 값이 있는 칸만 쓰므로 F열 수식을 지우지 않습니다 |
| C2 | 헤더 정규화(`normalizeHeader`)를 `getColumnMap`·`getRowDataAsObject`(LLM 프롬프트 키)·착수 메일 새 행·LLM 응답의 `열` 에 모두 적용 |
| C3 | LLM 이 쓸 수 있는 열 = 날짜 열(`시험시작일`·`1차결함`·`2차결함`·`3차결함`·`패치`·`시험종료일`) + `상태`. 검사는 `checkLlmUpdates()` (순수 함수): 허용 밖 열은 버림(로그·시뮬레이션에 남김), 상태는 `접수/진행/중단/종료` 가 아니면 확인 큐, 날짜는 `yyyy-MM-dd` 가 아니면 확인 큐, 기존 값이 있으면 확인 큐 |
| C4 | `cleanEmailBody()` 를 줄 단위로 다시 작성하고 STEP A·B 모두 자른 본문을 씁니다. 자르는 곳: `-----Original Message-----`/`-----원본 메시지-----`, Gmail `…님이 작성:`(두 줄로 꺾여도), `On … wrote:`, Outlook 머리말 묶음(`From:/보낸 사람:` + 다음 4줄 안의 `Sent:/To:/보낸 날짜:/받는 사람:` 등), 줄 맨 앞 `>`. `Forwarded message`/`전달된 메일` 아래는 자르지 않습니다. 자른 본문이 5자 미만이면 LLM 을 부르지 않고 처리로그에 `LLM 생략: …` 을 남깁니다 |
| 마스킹 | LLM 에 보내는 본문: IP, `+82 …`, `010.1234.5678`, `01012345678`, `02-123-4567`, `010-1234-5678` 을 가립니다 |
| 날짜 | 행 데이터의 Date 를 `yyyy-MM-dd`(Asia/Seoul) 문자열로 바꿔 프롬프트·충돌 검사에 씁니다 |

**아직 그대로인 것 (→ 2단계)**: 같은 날짜도 충돌로 봄(A1), 한 열이라도 확인 큐면 그 메일 전체 보류(A1), LLM 실패 재시도 없음(A2), 날짜 순서 검사 없음(A8). 프롬프트에는 아직 행 전체(담당자 포함)가 들어갑니다(A7).

### 2단계 — 자동화율 개선
| # | 할 일 |
|---|---|
| A1 | **같은 날짜는 충돌이 아닙니다.** 둘 다 `yyyy-MM-dd` 로 맞춰 같으면 건너뛰고, 다를 때만 그 열을 확인 큐로 보냅니다. 충돌이 없는 열은 반영합니다(지금은 하나라도 충돌하면 전부 보류) |
| A2 | **LLM 실패 재시도.** `callGeminiAPI` 가 실패 종류(일시 오류 429·5xx / 응답 해석 실패 / 안전 차단)를 돌려줍니다. 처리로그에 `상태`(완료·재시도대기·포기)와 `시도횟수` 열을 두고, 3회까지 다시 시도합니다. `getProcessedMessageIds` 는 `재시도대기` 를 처리된 것으로 보지 않습니다 |
| A3 | **시험번호 찾기 보강.** 제목에 없으면 같은 스레드의 다른 메일 제목에서 찾고, 그래도 없으면 발신 도메인을 `마스터` 의 담당자 메일 도메인과 맞춥니다. 후보가 하나일 때만 자동으로 처리하고, 0개나 여러 개면 확인 큐로 보냅니다(처리로그를 `포기` 로 남기지 않음) |
| A4 | **내 메일(`MY_EMAIL`)이면 STEP A(담당자 등 기입)를 건너뜁니다** |
| A5 | 직급 정규식에 넣는 이름을 이스케이프합니다(특수문자가 든 이름 하나로 실행 전체가 멈추지 않게) |
| A6 | 년도는 `new Date()` 가 아니라 시험번호의 두 자리(`-26-` → 2026)에서 뽑습니다 |
| A7 | 프롬프트 개선: 메일유형 후보 목록 명시, 행 전체 대신 허용 열과 그 현재 값만 전달, `generationConfig.responseSchema` 로 JSON 구조 강제 |

- **완료 기준**: 사본에서 같은 메일 묶음으로 처리했을 때, 1단계보다 확인 큐 건수와 `시험번호 없음` 건수가 줄고 잘못 들어간 값이 없습니다.

### 4단계 — 버전 관리와 계약
- `clasp` 로 이 폴더를 Apps Script 프로젝트와 연결하고 git 으로 관리합니다(`.clasp.json` 의 scriptId 는 넣어도 되지만 키·토큰은 넣지 않습니다).
- `SHEET_CONTRACT.md` 를 작성합니다: 탭별 열 목록, 각 열을 쓰는 쪽(사람/Flow/ATDT), 형식, 허용값, ID 규칙, 스키마 버전(`설명` 탭의 한 셀에 `schema: N`).

### 이후 (이 프로젝트 범위 밖)
- ATDT 의 구글 시트 읽기 연동 (진행 중인 건, 확인 큐, 새 착수 알림) → ATDT 레포에서 진행합니다.
- ATDT 가 `할 일` 탭을 옵시디언 일일노트에 반영. "당일 할 일은 넣지 않고 오늘 이후만" 규칙은 이쪽에서 적용합니다.
- 상태(E열)를 날짜 열에서 규칙으로 계산하는 방안 (LLM 의 `상태변경` 대체).

## 8. 개발 규칙 (Claude Code)

- 이 폴더의 `.gs` 파일만 고칩니다. 실제 시트와 Gmail 에는 직접 손대지 않습니다. 배포는 사람이 `clasp push` 하거나 편집기에 붙여 넣습니다.
- 시트 구조(탭·열·헤더 이름)를 바꾸는 변경은 **먼저 사람에게 확인**받고, `SHEET_CONTRACT.md` 와 이 README 를 함께 고칩니다.
- 사람이 해야 하는 작업(시트 수식, 스크립트 속성, 트리거 등록)은 단계 끝에 **"사람이 할 일"** 목록으로 따로 적습니다.
- 마스킹·인용문 절삭·허용 열 검사를 약하게 만드는 변경은 하지 않습니다.
- 커밋은 단계 단위로 나누고, 단계마다 무엇을 어떻게 확인했는지 적습니다.
