# Flow — GS 인증 메일 → 구글 시트 자동화 엔진

Google Apps Script 프로젝트. 업체·시험 관련 Gmail 을 읽어 **구글 시트(시험일정요약, `마스터` 탭)** 를 자동으로 갱신합니다.
목표는 완전 자동화가 아니라 **약 80% 자동화**입니다. 확실한 것은 자동으로 넣고, 애매한 것은 `확인 큐` 로 넘겨 사람이 정합니다.

현재 버전: **v1.6** — 4단계 중 `SHEET_CONTRACT.md`(schema 1) 작성 (아래 [현재 상태](#현재-상태)). 지금 할 일은 [사람이 할 일](#사람이-할-일-v16-기준--위에서부터-순서대로)·[다음 단계](#다음-단계-개발--순서대로)

---

## 1. 위치와 다른 프로그램과의 관계

```
Gmail ──▶ [Flow 엔진 (이 프로젝트, Apps Script)] ──▶ 구글 시트 ◀── [ATDT 허브 (Electron, 별도 레포)]
```

- **Flow 와 ATDT 는 분리된 프로그램입니다.** 서로 직접 호출하지 않고(웹앱·API 없음) **구글 시트만 접점**으로 씁니다.
- 각자 혼자서도 동작해야 합니다.
  - Flow 단독: 사람이 시트에서 직접 `확인 큐` 를 처리합니다.
  - ATDT 단독: 시트를 읽어 보여 주기만 합니다.
- 두 프로그램의 호환은 **시트 계약(`SHEET_CONTRACT.md`)** 으로 지킵니다. 시트 구조를 바꾸면 계약 문서를 먼저 고칩니다.
- **옵시디언 연동은 보류합니다.** Flow 는 옵시디언·GitHub 에 쓰지 않습니다. LLM 이 뽑은 할 일은 시트의 `할 일` 탭에 쌓아 두고, 나중에 ATDT 가 가져가 일일노트에 넣습니다.

## 3. 처리 흐름

### 3-1. 착수 메일 (매일 07시)
1. `subject:"GS 시험 인증 시작 안내" newer_than:3d` 로 검색합니다. `Re:`·`Fwd:` 메일은 건너뜁니다.
2. 본문에서 상담자, 시험안내일, 시험시작일, WD, 시험원을 뽑고 상태를 `접수` 로 둡니다.
3. `마스터` 에 새 행을 만들고 처리로그에 남깁니다.
4. **사람이 할 일**: 새 행에 시험번호를 적습니다.

### 3-2. 진행 메일 (매시간)
두 트리거는 잠금(`LockService`)으로 동시에 돌지 않고, 5분이 지나면 남은 메일은 처리로그 없이 다음 실행으로 넘깁니다.

0. **확인 큐 결정 반영**: `처리` 가 `적용`·`무시` 이고 `처리시각` 이 빈 행을 먼저 처리합니다(아래 3-3).
1. `GS` 라벨이 붙은 스레드 20개를 읽습니다. 처리로그에 있는 메시지ID 는 건너뜁니다(상태가 `재시도대기` 인 메일만 다시 처리).
2. 시험번호(`TTA-26-00001` 형식)를 **제목 → 같은 스레드의 다른 제목 → 메일 도메인**(업체 메일이면 발신자, 내 메일이면 받는 사람·참조) 순서로 찾아 `마스터` 의 행과 맞춥니다.
   - 도메인은 `마스터` 의 `담당자` 칸에 있는 메일 주소의 도메인과 맞춥니다. `종료`·`중단` 행과 공용 도메인(`CONFIG.SHARED_MAIL_DOMAINS`)은 보지 않습니다.
   - 후보가 하나일 때만 자동으로 처리합니다. 0개나 여러 개면 `확인 큐` 로 보내고 처리로그에 `확인대기` 로 남깁니다.
   - 시험번호는 찾았는데 행이 아직 없으면 로그를 남기지 않고 다음 주기에 다시 봅니다.
3. **STEP A (정형 파싱)**: 년도(시험번호에서)·기업명·담당자가 빈칸이면 채웁니다. 내가 보낸 메일이면 건너뜁니다.
4. **STEP B (LLM)**: 인용문을 자르고 마스킹한 본문과, 허용 열의 현재 값만 Gemini 에 보내 JSON 을 받습니다(`responseSchema` 로 구조 강제).
   - 코드가 검사합니다: 허용 열, 상태 허용값, 날짜 형식, 같은 날짜는 건너뜀, 다른 값이면 충돌, 날짜 순서.
   - 문제없는 열은 반영하고 문제 있는 열만 `확인 큐` 로 보냅니다. 확신도가 낮으면 아무것도 반영하지 않고 확인 큐로 보냅니다.
   - 요약은 `진행상황` 에 `[MM/dd] 요약` 으로 덧붙입니다.
   - LLM 이 뽑은 `할일` 은 `할 일` 탭에 `신규` 로 넣습니다. 같은 시험번호·내용·기한이면 넣지 않습니다. 확신도가 낮으면 넣지 않습니다.
   - LLM 실패: 일시 오류(429·5xx·네트워크)와 응답 해석 실패는 `재시도대기` 로 남겨 다음 주기에 다시 시도하고, 3번째에도 실패하면 `포기`. 안전 차단은 바로 `포기`. 키·모델 오류(4xx)는 처리로그 없이 실행을 멈춥니다.

### 3-3. 확인 큐 처리 (사람 또는 ATDT)
1. `확인 큐` 의 한 행이 바뀔 값 하나입니다. `처리` 드롭다운을 `적용` 또는 `무시` 로 바꿉니다. 적용 전에 `제안값` 을 고쳐도 됩니다.
2. 시트에서 바꾸면 onEdit 트리거(`onQueueEdit`)가 바로 반영하고, 트리거가 없거나 다른 프로그램이 바꾸면 다음 매시간 실행이 반영합니다.
3. `적용`: 마스터의 현재 값이 `기존값` 과 같을 때만 `제안값` 을 씁니다(날짜·상태 형식 다시 검사). 그사이 마스터가 바뀌었으면 쓰지 않고 `처리` 를 `대기` 로 되돌리며 `사유` 에 까닭을 덧붙입니다.
4. `시험번호` 행(시험번호를 못 찾은 메일)은 자동 적용하지 않습니다. 메일을 열어 직접 처리하고 `무시` 로 닫습니다.
5. 반영이 끝나면 `처리시각` 이 채워집니다. `처리시각` 이 있는 행은 다시 처리하지 않습니다.

## 4. 시트 구조 (요약 — 상세는 `SHEET_CONTRACT.md`)

| 탭 | 쓰는 쪽 | 내용 |
|---|---|---|
| `마스터` | 사람, Flow | 건당 1행, A~AO열. **2행은 예시 데이터이므로 지우지 않습니다.** 데이터는 3행부터 |
| `처리로그` | Flow | A 메시지ID · B 처리 시각 · C 결과 · D 상태(`완료`/`재시도대기`/`포기`/`확인대기`) · E 시도횟수. D1·E1 이 비어 있으면 코드가 헤더를 적습니다. D 가 빈 예전 행은 `완료` 로 봅니다 |
| `확인 큐` | Flow, 사람·ATDT(`처리`·`제안값` 만) | 머리글 1행. 변경 1건당 1행: ID(`Q-<메시지ID>-<n>`)·생성시각·시험번호·메시지ID·메일 링크(`#all/<threadId>`)·열·기존값·제안값·사유·LLM 원문·처리(`대기`/`적용`/`무시` 드롭다운)·처리시각. 비어 있거나 없으면 코드가 만듭니다 |
| `확인 큐 (v1)` | (보관) | v1.5 이전 형식(머리글 없음, 메일 1건당 1행)의 확인 큐. 처음 실행할 때 코드가 이름을 바꿔 보관합니다 |
| `할 일` | Flow, ATDT(`상태` 만) | 머리글 1행: ID(`T-<메시지ID>-<n>`)·시험번호·내용·기한(`yyyy-MM-dd` 또는 빈칸)·출처 메시지ID·생성시각·상태(`신규`/`반영`/`무시` 드롭다운). 없으면 코드가 만듭니다 |
| `설명` | 사람 | 사용 안내 |
| `시뮬레이션` | Flow (`DRY_RUN` 일 때만) | 시각·메시지ID·시험번호·탭·행·열·기존값·새 값·사유. **사본에서만** 없으면 코드가 만듭니다. 실제 시트에서는 만들지 않고 실행을 멈춥니다 |

- **열은 글자(R열)가 아니라 헤더 이름으로 찾습니다.** 헤더의 괄호 앞부분만 키로 씁니다(`담당자 (고객사 연락처/직함)` → `담당자`).
- **날짜는 `yyyy-MM-dd`(Asia/Seoul) 한 가지 형식으로** 비교·기록합니다.
- `F열(잔여일자)` 은 수식입니다. 스크립트가 쓰지 않습니다.
- 처리로그의 행을 지우면 그 메일을 다시 처리합니다(재테스트용).

## 5. 설계 원칙

1. **LLM 은 값을 제안만 하고, 반영 여부는 코드가 정합니다.** 열 허용 목록, 날짜 형식, 상태 허용값, 날짜 순서 규칙(시작 ≤ 1차결함 ≤ 2차결함 ≤ 3차결함, 패치 ≤ 종료)은 코드로 검사합니다. 하나라도 어긋나면 확인 큐로 보냅니다.
2. **LLM 이 쓸 수 있는 열은 날짜 열과 `상태` 뿐입니다.** `담당자`(파서가 채움), `진행상황`(코드가 요약을 덧붙이고 사람이 메모함), 시험번호, 기업명, 수식 열은 LLM 이 쓰지 않습니다.
3. **외부로 보내는 정보를 최소화합니다.** LLM 에는 인용문을 자르고 전화번호·IP 를 마스킹한 본문만 보냅니다. API 키는 URL 이 아니라 헤더로 보냅니다.
4. **덮어쓰지 않습니다.** 기존 값과 같으면 건너뛰고, 다르면 확인 큐로 보냅니다. 충돌이 없는 열은 반영합니다.
5. **실패한 일을 버리지 않습니다.** 일시적 오류는 다시 시도하고, 끝내 처리하지 못한 메일은 사유와 함께 남깁니다.
